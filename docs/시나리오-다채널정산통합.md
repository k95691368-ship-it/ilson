# 시연 시나리오 — 다채널 정산 통합

여덟 단계를 끝까지 지나간 사례 하나. 화면에 심을 데이터의 원본이다.

**전부 가상이다.** 실존하는 회사·부서·사람·브랜드가 아니다. 제품 브랜드는
시험 데이터 생성기(`seed/generate_sources.py`)와 같은 가상 브랜드 '누리에(NURIE)'를 쓴다.

## 1단계 — 신청서

| 항목 | 내용 |
|---|---|
| 신청 부서 | 재무 |
| 신청자 | 정산 담당자 |
| 병목 이유 | 매주 월요일마다 채널 5곳의 정산서를 손으로 붙인다 |
| 문제 상황 | 채널마다 양식이 달라 컬럼 맞추는 데만 한 시간이 넘는다. 지난주에는 오프라인 채널 파일 맨 아래 합계 줄을 같이 붙여서 매출이 두 배로 나온 걸 화요일에야 발견했다 |
| 바라는 해결 | 파일만 올리면 하나로 합쳐진 표가 나왔으면 한다 |
| 현재 소요시간 | 1명 × 주 1회 × "한 시간 반? 두 시간?" (체감) |
| 첨부 | 채널 원장 5종 (`seed/out/`) |

### 함께 접수된 다른 신청서

| 부서 | 내용 | 예상 판정 |
|---|---|---|
| 재무 | 정산 결과를 ERP 매출 모듈에 자동 등록 | **반려** — 외부 시스템 쓰기는 범위 밖 |
| SCM | 재고 소진일 2주 미만 품목 주간 확인 (재고 파일 × 판매 파일 브이룩업) | 수용 (후순위) |
| 마케팅 | 광고비 × 매출을 붙여 제품 단위 기여이익 ROAS | 수용 (후순위) |
| 영업 | 점포별 주간 실적을 담당자별로 8번 잘라 배포 | 접수 |
| 운영 | 고객문의 엑셀 유형 분류 후 담당자 배분 | 접수 |
| 마케팅 | 신제품 상세페이지 시안 자동 생성 | **반려** — 이미지 제작은 범위 밖 |
| 재무 | 분기 부가세 신고용 과세/면세 구분 | 보류 — 원천에 구분 자체가 없음 |

## 2단계 — 검토

**1순위로 정산 통합을 고른 근거**

> 주 1회 반복 × 다섯 부서가 결과를 쓴다 × 이미 오류가 실제로 발생했다(합계행 오적재).
> 임팩트는 가장 크고 난이도는 중간이다. 재고 소진일이 난이도는 더 낮지만, 그건 이
> 과제가 만드는 매출 데이터 위에서 하면 훨씬 싸게 붙는다. 순서를 바꾸면 두 번 일하게 된다.

**ERP 자동 등록을 반려한 근거**

> 외부 시스템에 쓰려면 계정 권한·실패 롤백·감사 추적을 전부 새로 설계해야 하고,
> 그건 이 도구가 감당할 범위가 아니다. 요청의 본래 목적은 "재입력 시간을 없애는 것"이므로,
> ERP 업로드 양식에 맞춘 파일까지 만들어 주면 목적의 대부분은 달성된다. 등록 버튼은 사람이 누른다.
>
> 고려했다 뺀 것: RPA로 화면을 자동 조작하는 안. 화면이 바뀌면 조용히 깨지고, 깨진 걸 아무도 모른다.

## 3단계 — 협의안

### 이해관계자와 각자가 원하는 것

| 부서 | 역할 | 원하는 것 |
|---|---|---|
| 재무 | 정산 담당 (주관) | 금액이 1원도 틀리지 않을 것. 틀리면 마감 후 정정 공시까지 간다 |
| 영업 | 채널 관리 | 월요일 오전 회의 전에 채널별 실적을 볼 것 |
| SCM | 수급 계획 | 판매 수량이 SKU 단위로 정확할 것. 세트 상품도 낱개 환산되면 좋겠다 |
| 운영 | 실무 수행 | 내가 매주 손댈 일이 없을 것. 붙여넣기만 하는 거면 안 하느니만 못하다 |

### 회의록 (1차 발굴 회의)

```
참석: 재무 정산 담당, 영업 채널 매니저, SCM 수급 담당, 운영 담당
일시: 화요일 14:00~15:10

(AX) 지금 이 일을 정확히 어떻게 하고 계신지부터 들을게요.
(재무) 월요일 아침에 채널 다섯 군데 정산서를 각각 다운받아요. 자사몰이랑 오픈마켓은
CSV고, 오프라인 채널은 엑셀, 해외 A는 CSV인데 달러고, 해외 B는 엑셀인데 시트가
월별로 나뉘어 있어요. 그걸 새 시트에 하나씩 붙이는데, 컬럼 이름이 다 달라서
순서 맞추는 게 제일 오래 걸려요.

(AX) 한 번에 몇 분쯤 걸리세요?
(재무) 재본 적은 없는데, 커피 한 잔 마시고 시작해서 점심 전에 끝나요.
한 시간 반? 두 시간? 바쁜 주에는 오후까지도 가요.

(AX) 틀렸을 때는 어떻게 아세요?
(재무) 대개 모릅니다. 지난주에는 오프라인 채널 파일 맨 아래 합계 줄을 같이 붙여서
매출이 두 배로 나왔는데, 화요일에 영업팀이 "이번 주 대박이네요?" 해서 알았어요.
그런 거 아니면 그냥 지나가요. 그리고 금액이 1원이라도 틀리면 안 됩니다.
마감 넘어가면 정정 공시까지 가는 일이라서요.

(영업) 저희는 월요일 오전 10시에 채널 회의가 있어요. 그때 채널별 실적이 있어야 하는데
지금은 못 받아서 지난주 숫자로 얘기하고 있습니다.

(재무) 그건 좀... 정확하게 하려면 시간이 걸리는데요.
(영업) 대충이라도 있으면 좋겠어요.
(재무) 대충은 안 됩니다.

(AX) 그 부분은 제가 따로 정리해서 다시 여쭐게요. SCM은요?
(SCM) 수량이 SKU 단위로 정확하면 좋겠어요. 그런데 채널마다 상품코드가 달라요.
오프라인은 자기네 코드를 쓰고 오픈마켓은 옵션ID를 써요. 같은 마스크인데 코드가 다섯 개예요.
그리고 세트 상품이요. 5매 기획세트 같은 게 팔리면 그건 낱개 5개로 봐야 하는데
지금은 그냥 1개로 잡혀 있어요.

(AX) 세트 구성이 어디 정리돼 있나요?
(SCM) ...그건 없네요. 담당자가 알고 있어요.

(운영) 저는 솔직히, 지금처럼 제가 매주 붙여넣기만 하는 거면 안 하느니만 못해요.
자동으로 안 되는 건이 몇 건씩 나올 텐데 그거 제가 다 처리해야 하면 시간이 똑같아요.

(AX) 자동으로 안 되는 게 몇 %쯤 나올 것 같으세요?
(재무) 미등록 코드는 매주 몇 개씩 나와요. 신상품 나오면 특히요. 열 개 안쪽?
(운영) 열 개면 괜찮은데, 그게 매번 처음부터 다시 판단해야 하는 거면 안 됩니다.

(AX) 한 번 판단한 건 기억해서 다음부터 자동으로 하는 걸로 하면요?
(운영) 그거면 됩니다.

(재무) 아 그리고 정산서 양식은 안 바뀌니까 한 번 맞춰두면 계속 쓸 수 있을 거예요.
(AX) 최근에 바뀐 적 있나요?
(재무) 작년에 오픈마켓이 컬럼 하나 늘렸던 것 같은데... 확실하진 않아요.

(AX) 이 표를 최종적으로 누가 보고 무슨 결정을 하나요?
(재무) 대표님 주간 보고에 들어가요. 채널별로 얼마 남았는지를 봅니다.
(영업) 저희는 어느 채널에 힘을 더 줄지를 정하죠.
(SCM) 저는 그거 보고 발주를 넣습니다.

(AX) 그러면 "얼마 팔았나"가 아니라 "얼마 남았나"가 필요한 거네요.
(재무) 네. 수수료랑 원가 빼고요. 그건 지금 표에는 없어요. 따로 계산합니다.
```

### 회의록에서 뽑은 요구 (인용은 위 원문에 실제로 존재해야 한다)

| 종류 | 부서 | 내용 | 인용 | 판정 |
|---|---|---|---|---|
| 제약 | 재무 | 정답 대비 금액 오차 0원 | "금액이 1원이라도 틀리면 안 됩니다" | 채택 |
| 요구 | 영업 | 월요일 10시 회의 전 산출 | "월요일 오전 10시에 채널 회의가 있어요" | 채택 |
| 요구 | SCM | SKU 단위 수량 집계 | "수량이 SKU 단위로 정확하면 좋겠어요" | 채택 |
| 제약 | 운영 | 같은 판단을 두 번 요구하지 않을 것 | "매번 처음부터 다시 판단해야 하는 거면 안 됩니다" | 채택 |
| 요구 | 재무 | 매출이 아니라 기여이익 | "수수료랑 원가 빼고요" | 채택 |
| 요구 | 영업 | 잠정 수치라도 먼저 | "대충이라도 있으면 좋겠어요" | **기각** |
| 미결 | SCM | 세트 구성 정보가 없다 | "그건 없네요. 담당자가 알고 있어요." | 채택 |
| **가정** | 재무 | 정산서 양식이 안 바뀐다고 전제 | "정산서 양식은 안 바뀌니까" | **수정 채택** |
| 요구 | 운영 | 미처리 주당 10건 이내 + 기억 | "미등록 코드는 매주 몇 개씩 나와요" | 채택 |
| 요구 | 재무 | 대표 주간 보고에 들어간다 | "대표님 주간 보고에 들어가요" | 채택 |

**"대충이라도" 기각 근거**
> 잠정 수치와 확정 수치가 같은 화면에 있으면 어느 쪽이 인용될지 통제할 수 없다.
> 대표 보고에 잠정치가 들어가면 정정 비용이 크다. 요구의 본래 목적은 "월요일 회의에서
> 숫자를 보는 것"이므로, 일요일 밤 사전 실행으로 목적을 달성한다.
> 고려했다 뺀 것: 잠정 수치에 워터마크를 붙이는 안 — 실무에서 워터마크는 캡처되며 사라진다.

**"양식 안 바뀐다" 수정 채택 근거**
> 본인도 "확실하진 않아요"라고 했다. 확인되지 않은 가정 위에 설계하면 바뀌는 날 조용히
> 틀린다. → 헤더 지문이 이전과 다르면 자동 매핑을 멈추고 사람에게 확인을 요청한다.

### 요구 충돌과 판정

| 충돌 | 맞바꾸는 것 | 판정 | 근거 |
|---|---|---|---|
| 오차 0원 ↔ 월요일 마감 | 정확도 ↔ 마감시각 | **정확도 우선** | 틀린 숫자가 대표 보고와 정정 공시로 이어지는 비용이, 영업이 하루 늦게 보는 비용보다 크다. 다만 금요일 마감분을 일요일 밤에 미리 돌려 두면 대개 09:30 안에 끝난다. 못 끝내는 주에는 정확도를 택한다 |
| 사람 개입 0 ↔ 오차 0원 | 자동화율 ↔ 사람 개입 | **절충** | 운영이 못 견딘다고 한 것은 개입 자체가 아니라 **반복**이었다. 추정하지 않고 격리하되, 한 번 확정한 별칭은 다음부터 자동 적용한다. 개입 건수는 주차가 지날수록 0에 수렴한다 |
| SKU 정확 집계 ↔ 세트 구성 정보 없음 | 완결성 ↔ 지금 있는 자료 | **세트 환산 제외** | 구성 정보가 문서로 없는 상태에서 담당자 기억으로 환산표를 만들면 틀렸을 때 아무도 모른다. 없는 자료로 만든 숫자는 없는 것보다 나쁘다 |

### 합격 기준 (만들기 전에 정한다)

| # | 기준 | 판정 방식 | 필수 안전 |
|---|---|---|---|
| 1 | 정답셋 대비 채널별 순매출 합계 오차 0원 | 규칙 | ✅ |
| 2 | 격리해야 할 행을 빠짐없이 격리하고, 정상 행은 격리하지 않는다 | 규칙 | ✅ |
| 3 | 외화 매출은 반드시 원화 환산 후 합산 | 규칙 | ✅ |
| 4 | 같은 파일을 두 번 올려도 합계가 변하지 않는다 | 규칙 | ✅ |
| 5 | 한 번 확정한 별칭은 다음 실행에서 사람 개입 없이 자동 적용 | 규칙 | |
| 6 | 헤더 지문이 다르면 자동 매핑 대신 검토함으로 | 규칙 | |
| 7 | 기여이익이 순매출→수수료→원가→물류→광고 순서로 계산 | 규칙 | |
| 8 | 결과의 모든 행이 원본 파일의 시트·행 번호로 되짚어진다 | 규칙 | |

> 필수 안전을 넷으로 제한한 근거: 전부 필수로 만들면 필수의 뜻이 없어지고,
> 사소한 회귀에도 배포가 막혀 게이트가 무시당하기 시작한다. "틀리면 돌이킬 수
> 없는 것"에만 붙였다.

### 기준선 실측 (3회)

회의에서 나온 "한 시간 반? 두 시간?"은 기준선이 될 수 없다. 실제로 세 번 재서 봉인한다.

| 회차 | 소요 | 오류 | 단계별 |
|---|---|---|---|
| 1 | 108분 | 1건 | 다운로드 7분 / 붙여넣기 65분 / 코드 맞추기 26분 / 검산 10분 |
| 2 | 97분 | 0건 | 다운로드 6분 / 붙여넣기 55분 / 코드 맞추기 26분 / 검산 10분 |
| 3 | 121분 | 2건 | 다운로드 8분 / 붙여넣기 70분 / 코드 맞추기 33분 / 검산 10분 |

**봉인값: 중앙값 97분, 표본 3회.**
표본이 3이므로 **신뢰구간을 붙이지 않고** "표본 3회 — 통계적으로 취약함" 경고를 상시 표시한다.

> 근거: 절감액은 이 값 위에서 계산되고, 나중에 반드시 "그 시간은 어떻게 아셨어요?"라는
> 질문을 받는다. 만든 사람이 자기 입으로 말한 숫자는 근거가 아니다.
> 고려했다 뺀 것: 담당자에게 지난 4주를 회상해 적게 하는 안 — 회상 편향이 크고 바쁜 주가 과대 대표된다.

## 4~8단계
