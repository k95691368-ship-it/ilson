현재 코드와 README에서 확인한 핵심 사용자는 사내 AI 도구를 사용하는 직원과 개선 담당자이다. 신청·검토·협의·제작·베타·성과 및 현장 피드백·문제 분석·실험·재측정의 연결을 유지한다. 이번 회차는 코드 검토와 PostgreSQL 재현을 통해 필수 문제를 최대 5개 선정하는 단계다. 후보는 오래된 사건의 새 안내 접근, 근거 부족 표본의 재검토, 권한 범위와 공유 문제 집계의 표시 일관성, 참여 부서 접근, 사용량 제한의 조회·복구 일관성이다. 아직 재현을 완료하지 않은 후보를 확정된 결함으로 취급하지 않는다.

작업 시작 시 work/progress.md와 로컬 5187 리스너는 없었다. 회차 종료 조건에는 빌드, 실제 API를 사용하는 로컬 서버 실행, 브라우저 동작 검증, 검증용 데이터 정리를 포함한다. 이전 테스트용 프로세스를 살아 있다고 가정하지 않는다. 사용량 조회는 일반 사용 가능, 주간 사용률 46%를 반환했다. 사용량은 조회 시점의 계정 값이며 잔여 토큰 수로 환산하지 않는다.

독립 읽기 검토와 메모리 PostgreSQL 재현으로 다섯 항목을 선정했다. 첫째, 본인 제보 101건 중 가장 오래된 제보에 새 안내를 등록하면 unread=1이나 cases 100건에 안내가 없었다. 생성순 커서 탐색을 추가하며, 최신 활동순만 바꾸는 방법은 미확인 100건 초과를 해결하지 못해 제외한다. 둘째, insufficient 판정 뒤 근거를 확보해도 재점검은 409, 재추출은 400이었다. insufficient만 비종결로 다루고 이전 판단은 추가 이력으로 보존한다. 셋째, 직원별 GET에서 공유 문제 2건이 1건으로 축소되면서 비용·우선순위는 공유 값으로 남았다. 원문 접근 범위는 좁힌 채 기존 보호된 집계 함수로 전체 문제 건수를 계산하고 열람 가능한 원문 수를 별도로 표시한다. 넷째, 참여 부서의 부서 자격 검사는 통과해도 해당 신청 조회가 404였다. 자유 입력 로그를 권한으로 해석하지 않고 인증된 담당자가 명시적으로 등록한 참여 범위를 사용한다. 다섯째, 실제 한도가 소진되어도 remainingToday=1이며 실패 반환 뒤 hit 수가 1로 유지되었다. 일반 제한 테이블을 개방하지 않고 전용 RPC에서 버킷·티켓·활성 계정을 검증한다.

우선순위는 업무가 멈추는 참여 부서 접근(P1, 중간 규모)이며, 안내 접근·재점검·집계·한도 일치(P2, 소규모~중간 규모)를 병렬 보완한다. 회귀 검증은 실제 scoped PostgreSQL 핸들러와 화면 상호작용을 결합한다. 정상 부서와 제외 부서, 100건 경계, 확정 판정의 덮어쓰기 금지, 이전 증거 보존, 다른 사람 원문 비노출, 한도 소진·반환·다른 티켓 거부를 완료 기준으로 둔다. root는 집계·로컬 실행·통합 검증을, 독립 작업은 feedback 범위와 participation/quota 범위로 분리한다. migration loader와 health 통합은 root만 수정한다.

집계 구현은 overrideMetrics의 보호된 공유 집계와 별도 열람 가능 건수, OverridePage의 원문 접근 범위 안내로 반영했다. 현재 마이그레이션 초안을 포함한 accessScopePostgres·essentialWorkflowUi·auditHardeningPostgres·httpBoundaryHardening 4파일 60개 테스트가 통과했다. 이는 전체 테스트·화면 검증의 대체가 아니다. 0008·0009 로더 및 readiness/health 검사 연결을 진행했고, 표본 묶음도 LIMIT 50 뒤에는 재점검 경로가 없는 동일 유형 문제를 추가 발견하여 재점검 지속성 항목에서 함께 보완 중이다.

피드백·표본 묶음의 독립 커서, 부족 판정 재검토와 DB append-only 이력, 관리자 참여 부서 명시 확인 화면, 계정별 도구 한도 조회·반환을 반영했다. 실제 화면 진입 중 확인한 부수 회귀(GET /demo/workspace 비활성 조회까지 차단)를 수정했으며 나머지 데모 쓰기·인증 보호는 그대로 검증했다. 1차 전체 검사에서는 1,567개 중 1개가 미사용 응답 필드 2개를 발견했다. 불필요한 값은 제거하고 원본 집계 범위를 인사이트에 표시해 재검사 중이다. 부족 판정을 최종 완료처럼 읽지 않도록 수치 제목도 ‘점검한 표본’으로 고쳤다.

localhost:5188 가상 계정 검증 서버(세션 72682)에서 브라우저로 참여 권한 명시 확인, 101번째 제보 안내 열기·읽음(1→0)·미해결 후속 과제 생성, 51번째 점검 묶음의 insufficient→issue와 이전 이력 2회 표시를 실행했다. 원본 스냅샷은 그대로 표시되며 최종 판정 입력창이 사라졌다. 390px 화면에서 문서 너비 375px로 가로 넘침이 없었고 페이지 이동 버튼과 본문 배치를 확인했다. 가상 계정·서명키·기록은 메모리 전용이며 종료 시 모두 소멸한다. tests/fixtures/localAccess.mjs는 같은 경계를 재현하는 재사용 검증 소스이고 임시 사용자 데이터가 아니다.

최종 검증은 전체 99파일 1,574개 테스트 통과(일반 1,568개 + 규모 6개), 마지막 문구 변경 관련 3파일 19개 재검사, 전체 린트와 클라이언트·Worker 빌드 성공이다. scripts/dev-demo.mjs를 최신 마이그레이션까지 갱신하고 가상 계정 회귀 fixture 옵션을 추가했다. 기존 검증 서버 77388·72682를 종료하여 메모리의 검증 계정·키·데이터를 정리했으며, 새 로컬 서버 세션 97324를 실행했다. http://127.0.0.1:5187/api/health가 ready=true·db/schema/runtime/capacity=true를 반환했고, 브라우저에서 새 개인 체험 생성과 운영판 표시를 확인했다. 이는 Supabase 호환 메모리 PostgreSQL 검증이며 운영 Supabase 연결 확인이 아니다. 운영 마이그레이션·외부 서비스·실제 고객 업무 효과·커밋·푸시·원격 배포는 범위 밖으로 미실행했다.

## 회차 2 — 필수 개선 로컬 반영 확인 (2026-09-19)

사용량 조회는 일반 사용 가능, 주간 사용률 51%(남은 비율 49%)를 반환했다. 회차 1 이후 소스·화면에서 추가로 확인할 후보는 도구 실행 실패 시 성공 결과까지 실패로 분류해 재기록하는 경로, 500건 범위 밖의 원본 판단 사건 접근, 소유계정이 없는 이전 신청의 명시적 권한 복구 경로다. 아직 재현·대안 비교를 마치지 않았으므로 구현 항목으로 확정하지 않았다. 미완료 항목을 우선 분석하고 필수 문제가 확인되면 최대 5개를 선정한다.
